# Лица в кадре: замер моделью вместо «на глаз»

Правило «ни одна надпись не на лице, подбородок над субтитрами» проверяется числом. Модель поиска лиц (YuNet) даёт рамку лица на каждом кадре. Из этих рамок считаются:
- свободные зоны для хука и плашек;
- высота субтитров;
- место мемов;
- аудит готового рендера.

## Установка

- **Модель** — `face_detection_yunet_2023mar.onnx` из официального репозитория OpenCV, `opencv/opencv_zoo`, папка `models/face_detection_yunet/`, 232 589 байт. Прямая ссылка на файл, а не на указатель Git LFS: `https://media.githubusercontent.com/media/opencv/opencv_zoo/main/models/face_detection_yunet/face_detection_yunet_2023mar.onnx`. Положить вне проекта, например `~/.config/reels-montage/models/face_detection_yunet.onnx`.
- **OpenCV ≥ 4.8**: `opencv-python-headless`. Можно не ставить в систему, а запускать через `uv run --with opencv-python-headless python …`. В OpenCV 5 Haar-каскадов больше нет, работает только `cv2.FaceDetectorYN`.

```python
d = cv2.FaceDetectorYN_create(model_path, "", (320, 320), 0.6)  # порог уверенности 0,6
d.setInputSize((w, h)); _, faces = d.detect(img)                 # faces[i][:4] = x, y, w, h; faces[i][14] = score
```

Нет модели — всё работает по-старому: агент смотрит кадры с сеткой и задаёт рамку головы руками.

## 1. Замер по черновику (после `cut.py`)

1. Кадры `final.mp4` каждые 0,25 с одним проходом ffmpeg: `fps=4,scale=540:960:force_original_aspect_ratio=increase,crop=540:960`. Половина размера: быстрее, а лица находятся так же.
2. YuNet на каждом кадре, рамки ×2 → координаты 1080×1920.
3. Сохранить в `edit/<id>/faces.json`: `{step, samples: [{t, faces: [[x,y,w,h,score], …]}]}`.

Скорость: около 10 с на 30 с видео (≈110 кадров). Лиц нет нигде (закадровый голос) — так и записать: графика свободна.

## 2. Камера

Виртуальная камера `{z, cx, cy}` двигает лицо. Экранные координаты рамки:

```text
x' = (x − cx)·z + 540      y' = (y − cy)·z + 960      w' = w·z      h' = h·z
```

Всё, что ниже, считается для крупности конкретного участка. На крупном плане лицо больше и ниже.

## 3. Зоны по участкам

Для каждого участка плана берётся общая рамка всех лиц за его время, с камерой, и запас **60 px**. Из неё считается:

| Зона | Как считается | Для чего |
|---|---|---|
| «Потолок» | y от 250 до верха лица − 60, если ≥ 120 px | хук, плашки |
| «Грудь» | от подбородка + 60 до верха субтитров − 20, если ≥ 120 px | плашки, чипы |
| Слева | от 40 до лица − 60 | плашки, мемы, иконки |
| Справа | от лица + 60 до 960 (правые 120 px — лайки) | плашки, мемы, иконки |
| Субтитры | подбородок + 30 ≤ верх субтитров | иначе опустить субтитры до подбородка + 30, но не ниже y ≈ 1390 (низ 420 — интерфейс); не помещается — общий план или камера ниже |
| Макушка | верх лица < 0 | срезана краем кадра |

**Реальный случай.** Крупный план видео-визитки: подбородок на крупных планах камеры доходил до y ≈ 1320. Субтитры стояли на 1350, и аудит показал 0 пересечений. С субтитрами на 1290 подбородок заходил бы в них почти на всём ролике. Отсюда правило для шаблона: верх субтитров = максимум подбородка (с дрейфом камеры) + 30, в пределах 1250–1390.

## 4. Проверка графики

Каждую плашку, хук или CTA-карточку поверх видео заносят в план как зону `keep_clear`: интервал, рамка `x,y,w,h` и что это. Агент сразу проверяет её против лиц за этот интервал, с камерой участка и запасом 60 px. Если плашка задевает лицо, её сдвигают в зону из пункта 3. Эти же зоны не закрывают мемы.

## 5. Аудит готового рендера

**Когда.** До показа человеку.

**Как.** Тот же замер, но по **рендеру**: камера, B-roll и графика уже применены, поэтому лица стоят там, где их видит зритель. Отсчёты каждые 0,25 с сверяются:
- **с полосой субтитров** — там, где звучит речь. Полосу передать фактическую: верх и низ плашки субтитров;
- **с зонами `keep_clear`** — плашки, хук, CTA;
- **с рамками мемов**;
- **с краем кадра** — не срезана ли макушка.

**Результат.** Пересечения с таймкодами, код выхода 1 → поправить и перерендерить. Графику, не занесённую в `keep_clear`, аудит не видит. Её проверяют стоп-кадры и раскадровка.

**Проверено.** Утверждённый ролик (субтитры на 1350): 107 кадров, 0 пересечений. Та же раскладка с субтитрами на 1290: пересечения почти по всей длине. Плашка, нарочно поставленная на лицо, поймана.

## 6. Мемы

Рамки лиц для мема берутся из `faces.json` за интервал мема, с камерой участка. Если замера нет, модель смотрит три кадра мема. Дальше выбирается слот (`inserts.md` → «Размер и место»).

**Проверено.** Рамки модели совпали с ручной разметкой на общем и на крупном плане. Выбранные слоты те же.
