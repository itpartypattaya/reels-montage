# Scripts: which one for which step

The plugin ships Python scripts for every repeatable step. **Run them; don't rewrite them for a video.** Everything
that differs between videos lives in JSON files of the video (`edit/<id>/cut.json`, `reel.json`, `visual_plan.json`),
not in code. Each script prints its full help with `--help`.

## How to run

```bash
cd {{PROJECT_ROOT}}
python "${CLAUDE_SKILL_DIR}/scripts/<name>.py" <command> [args]
```

- Use `python3` where `python` is Python 2 or missing; on Windows `py -3` also works. Python 3.9+ and ffmpeg/ffprobe
  in PATH. Pillow (`pip install Pillow`) for contact sheets, covers, brand logos and meme previews; OpenCV
  (`pip install opencv-python-headless`) only for face measurement.
- Run from the project folder: the scripts find it as the current folder or above (the nearest folder with `edit/` or
  `brands/`, or `it-reelsmaker.json -> project_root`), or from `REELS_PROJECT`. `edit/<id>` arguments are relative to it.
- The scripts write only into the project (and the Remotion project you name), never into the plugin folder: an
  update replaces it. Your own defaults go into `{{PROJECT_ROOT}}/reel-defaults.json` (`reelcfg.py defaults`; layers:
  `references/brands.md`, “Your settings in the project”).
- Exit codes: `0` done (warnings start with an exclamation mark and don't stop the edit); `1` a check failed (plan errors, a
  rough cut whose video and audio don't line up, a master that missed the target): fix it before going on.
- Several sessions in one project are safe: shared JSON is written atomically under a lock.

## The rough cut list (`edit/<id>/cut.json`)

```json
{
 "speed": 1.15,
 "sources": {"main": {"file": "IMG_4821.MOV"}},
 "look": {"correct": "colorchannelmixer=rr=0.97:bb=1.06", "lut": "brand", "lut_mix": 0.6, "grade": "eq=contrast=1.05:saturation=1.04"},
 "ranges": [{"start": 1.567, "end": 12.967, "beat": "hook", "speaker": "A"},
            {"start": 14.767, "end": 20.767, "beat": "the answer", "speaker": "B",
             "speakers": [{"from": 18.2, "to": 19.1, "speaker": "A"}]}],
 "fix": {"Akme": "Acme"},
 "retime": [{"text": "shortlist", "at": 16.16, "start": 16.10, "end": 16.62}]
}
```

`ranges` come from `speech_mask.py` (it prints them in this form), `look.correct` from `balance.py --write`. Two cameras: two `sources`, each with its own
`speed`, and `"source"` in every range. Cutaways from the same footage: `"extract": {"broll_view": {"start": 36.5,
"end": 41.5, "what": "the view from the balcony"}}` (`what` is optional: the description `footage.py` searches; the
clip is already in the rough cut's color, and `footage.py pick` takes it without a second look). Transcription fixes go into `fix` (every occurrence) or `fix_at` (one occurrence near a second; `at` is the word's start
after `retime`, so for a retimed word its new `start`); with several pieces of one long recording as sources (each starts at 0 s), give `fix_at`, `retime` and `keep` entries their `"source"`. A punchline the subtitles must not split (“Bar” holds 4 words / 26 characters per plate, “Accent” 3 / 20, “Typewriter” 10 / 52, and a 5-word joke over two plates reads in two beats) goes into `"keep": [{"text": "it", "at": 41.2, "words": 5}]`: the first word as the transcript has it, its start after `retime` (±0.02 s), the number of subtitle words from it (2 or more; a punctuation token is part of its word, a word removed with `fix_at → ""` is not counted), `"source"` optional. `captions.json` words get the group id (`"keep": "k1"`; a phrase the cut shows twice: `k1`, `k1-2`); the kit puts the group on one block past the mode's limits, two lines if needed (shown together, lifted to end above y 1500; a scene window inside the group drops none of its words, a group mostly under windows is hidden whole), and splits a group too wide even for two lines as if it had no mark (a warning in the Remotion log with `--log=verbose`). `subs.py` never splits a group between two phrases; the translation has no word-to-word map, so the mark reaches `captions-<lang>.json` only when it covers a whole phrase (`apply` names a group inside a longer phrase); `srt` keeps a group in one subtitle when it fits. Two people: `"speaker"` on each range and `"speakers"` (source seconds, a
word belongs where its middle is) for a switch inside one; `cut.py` puts the label on every caption word, `captions.json →
"speakers"` lists them sorted, and the kit colors the subtitles per speaker (`references/skit.md`). Without them a
transcript's own labels (`"speaker"` or `"speaker_id"`) are kept.

## What the scripts don't do

The kit (`assets/remotion-kit/`, copied into the Remotion project by `kit.py`) renders the `ReelKit` and `ReelCover`
compositions from the props of `visual_plan.py export --props`: rough cut, subtitles, brand, inserts, designed scenes,
cover, the virtual camera from `camera.json`, the three subtitle modes and the “framed” layout (`props.framed`). A per-video composition reuses its exported pieces (`FramedFootage`, `FramedLabel`, `EndCard` with the logo sting, `Corner`, `cameraAt`) instead of copying them. Anything a video needs beyond that (techniques, code scenes: `references/camera.md`,
`references/techniques.md`) is written by the agent per video, on top of the kit's components. A different transcriber is fine: run it on the WAV from `transcribe.py audio` (a tool that pulls the audio out of a phone MOV itself gets every word ~0.1 s early), and its output only has to pass `transcribe.py check`.

Audio extraction writes `edit/<id>/audio16k-<source stem>.wav` for each source, with source identity metadata next to it. Pass that WAV to `speech_mask.py`. Older projects may still use `audio16k.wav` as a legacy input; new transcriptions never reuse it. Cut ranges must be finite, inside the source (one frame of end tolerance), and contain at least one output frame. Segment output sizes must match; SAR is normalized to 1:1. Extract and matte names must be safe local names.
